## 2. Decision points

### (1) Git as canonical for infrastructure code — **ratify**
Effectively true since the June-2 reconciliation (`a195412`) and reinforced this run (drift export + the `database` CI replay). **Recommendation: ratify formally.** Tradeoff: none material — it matches reality.

### (2) Artifact/schema flow ECB→git as one-way projection — **ratify + automate the gate**
The projection mechanism is the migration export. It works but is **manual and was not enforced**, so drift accumulated silently. The `database` CI job + `ecb-migration-drift.py` already exist to catch this — they just weren't gating.
- **Recommendation:** make drift a **CI gate** — run `ecb-migration-drift.py` against prod in CI (read-only, needs a `SUPABASE_ACCESS_TOKEN` secret) and fail on applied-not-in-repo. This operationalizes one-way projection without new infrastructure.
- **Bidirectional paths to kill:** none found on disk. If any exist on other devices (Obsidian plugins, shortcuts writing to ECB *and* a synced file), they are out of view here and should be enumerated per-device before trusting this conclusion.

### (3) Obsidian / iCloud role — **formalize as local scratch (not a projection target)**
It is already only a symlink-attached local vault, not a synced store.
- **Recommendation:** formalize Obsidian as **human scratch / skills-host**, explicitly *not* a canonical or projected artifact store. Tradeoff: if you want artifacts readable in Obsidian, that should be an explicit *export* (ECB→file, one-way), never a writeback.

### (4) `~/ecos` workdir — **formalize as THE infra working tree (question is moot)**
The inherited "fold into ECOS-build vs formalize as ephemeral" choice is moot: `~/ecos` **already is** the ECOS-build checkout, versioned.
- **Recommendation:** drop the "ephemeral/unversioned" framing entirely; document `~/ecos` as the canonical infra working tree. Tradeoff: none.

### (5) Two-repo split (ECOS vault vs ECOS-build infra) — **keep, with a caveat**
The "thinking vs infra" rationale (BRAIN `c677c5b8`) stands. But the vault repo is **dormant locally** (no checkout), so the split currently earns its keep only conceptually.
- **Keep (recommended):** clean separation of governed thinking from deployable infra; smaller blast radius; matches the standing April-2026 decision. Cost: a second repo that is currently unused locally.
- **Merge (not recommended now):** one repo to track. Cost: re-litigates a deliberate decision, mixes vault prose with deploy surfaces, and there is no evidence of pain from the split — only of the vault being unused.
- **Recommendation:** keep the split; separately decide whether the **vault repo should be retired or actually used** (right now it is neither — a latent ambiguity worth closing).

## 6. Operational follow-ups surfaced (not part of the topology decision, but adjacent)
- **Deploy-tooling gap:** Supabase CLI 2.75.0 cannot deploy the ecb-mcp edge function because the (gitignored, locally-regenerated) `deno.lock` is version 5. Fix: upgrade the deploy CLI to ≥2.105.0, or deploy without the local lock. This blocked the embeddings edge-fn deploy this run.
- **CI deploys nothing:** the `ecb-mcp` CI job only `deno check`s; combined with the above, the function can pass CI yet be undeployable with the pinned CLI. Worth aligning.
- **Drift gate:** add `ecb-migration-drift.py` to CI (see §2.2).
